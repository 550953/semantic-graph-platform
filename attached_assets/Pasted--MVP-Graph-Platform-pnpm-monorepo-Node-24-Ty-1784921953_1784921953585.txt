Привет! Мы приступаем к активной разработке MVP платформы Graph Platform (pnpm monorepo, Node 24, TypeScript 5.9 strict, Express, Drizzle ORM + Supabase Postgres). 

Текущее состояние: настроена инфраструктура, деплой на Render, подключена БД через Drizzle, есть /healthz роут. Функциональность базы данных и API в папках lib/db и artifacts/api-server пока пустая (~5% готовности).

Наша цель — двигаться итеративно, закрывая задачи небольшими осязаемыми кусками с работающим кодом на выходе. 

Ниже представлен план на первые две фазы. Наша первоочередная задача — реализовать Фазу 1 (База данных) и Фазу 2 (Базовый CRUD API для графа).

---

### План работ для старта:

#### ФАЗА 1: Базовая схема данных (Drizzle ORM + Миграции)
Необходимо спроектировать и описать через схемы Drizzle следующие базовые сущности графа и окружения:
1. Workspace, Portfolio, Project (иерархия организации).
2. Actor (Human | AI | Service | External) вместо абстрактных пользователей.
3. NodeType & EdgeType (онтологический базис).
4. Node & Edge (основные сущности графа: ID, тип, JSON-метаданные, связи с Workspace/Project).
5. Issue / WorkItem (базовая сущность для задач, дефектов, рисков).
6. Настроить механизм миграций (drizzle-kit).

*Критерий приемки Фазы 1:* Схемы описаны в коде, миграции успешно применяются к нашей базе данных в Supabase, есть TypeScript-типы для всех сущностей.

#### ФАЗА 2: Graph Engine API (CRUD узлов и рёбер)
На базе созданной схемы поднять первые эндпоинты в Express API-сервере:
1. CRUD для Workspace, Project.
2. CRUD для Actor.
3. CRUD для узлов (Nodes) и рёбер (Edges) графа с фильтрацией по типу и проекту.
4. Обновить OpenAPI-спецификацию (использовать/проверить Orval кодогенерацию для клиента).

*Критерий приемки Фазы 2:* Эндпоинты отвечают через HTTP, валидируются схемами (например, Zod), в базе реально создаются и читаются узлы/связи.
